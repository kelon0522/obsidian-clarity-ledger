## 待办拖拽两条新规则（feat，commit 81c27ae）

**需求**（主理人）：已完成待办不能拖；未完成待办可拖到其他日期，拖后整条转移过去。

**实现**（三处生产代码）：

1. `src/store/index.ts` — 新 action `moveTaskToDay(id, toKey)`：
   从未完成待办所在天移除、追加到目标天末尾（目标天不存在就 `day_` 建档），
   目标天跑 `reflow` 守「计划列顺延」；**两天都 markDirty**（少写一天=搬了一半）；
   拒绝已完成（`act != null`）与同日移动；notify「已移至 MM-DD：标题」，不带撤销
   （撤销快照是单天的，跨天给不了 —— 别放个按了没反应的按钮）。
2. `src/components/TodoList.tsx` — 已完成行 `draggable={!done}` +
   `useSortable({ disabled: { draggable: done, droppable: false } })`
   （拖不了但仍可以被别的项插到前后）+ dragstart 里再拦一道（双保险）。
3. `src/components/Calendar.tsx` — 日期格接 onDragOver/onDrop/onDragLeave；
   只接受「来自待办区 + 当天存在 + 未完成 + 不是当天」的 payload；
   悬停加 `.cl-day.drop` 高亮（CSS 加在**隔离层**即 @layer 外，
   进了 layer 会被主题的 button 样式压掉）。

**踩到的真 bug**：任务搬走后源行被 React 卸载 → dragend 冒泡不到根容器 →
payload 残留。后果：之后从别处拖东西上月历，onDayOver 会把残留当成待办接。
修法：onDayDrop 里显式 `setDragPayload(null)`（不能只等 dragend）。
**这条是跑冒烟测试时才暴露的** —— DOM 属性断言（draggable=false）永远抓不到它。

**dnd-kit 查证**（node_modules 源码）：
- `useDraggable` 里 `listeners: disabled ? undefined : listeners`（core.cjs.development.js:3443）
- `normalizeDisabled(true)` → `{ draggable: true, droppable: true }` ——
  **布尔值会把两者一起关掉**，要「不可拖但仍是落点」必须写对象形式。

**测试**：store 10 条 + 冒烟 4 条（伪造 DataTransfer + 派发 bubbling/cancelable
的原生事件，跑完整 dragstart→dragover→drop 链路；React 18 监听器在根容器，
不冒泡收不到）。变异 18 → 23（5 条新的：draggable 开关 / dragstart 拦截 /
act 判断 / 同日判断 / markDirty(toKey)）。**npm test 263 全绿**（上一条记录里的
225 已过时），npm run build 通过。

**写测试踩的坑**：新 describe 必须自己带 beforeEach/afterEach ——
第一个 describe 的清理管不到别的 describe，漏了的话 root 不卸载、
host 越积越多，`querySelectorAll` 会数到别的用例的行（当时数出 5 行）。

**类型坑**：`[...document.querySelectorAll(...)]` 在 tsc 下报 TS2488
（tsconfig 没开 `DOM.Iterable`）—— vitest 不做类型检查所以测试全绿，
只有 `npm run build` 里的 tsc 会拍到。改用 `Array.from(...)`（array-like 重载）。

**产物验证小坑**：esbuild 默认把非 ASCII 转成 `\uXXXX` 转义（大写十六进制），
用 grep 直接搜中文字符串查不到 —— 要用 node 读文件或搜转义序列。

## 变异复验：`~`（wrong-assertion）不算失败，别只看最后一行

第一轮变异跑出 **22✓ + 1~**，而脚本末尾照样打印「全部 23 个变异都被抓到」——
因为 `mutation.sh` / `mutation.mjs` 只在 `✗`（green / crashed）时 `survived++`，
`~` 不计数。**「拖回当天」那条的 ~ 暴露了两个真问题**：

1. **store 用例选了「本来就在末尾」的任务**（第 3 条）——
   `moveTaskToDay` 去掉守卫后的行为是「原地移除 → 追加到末尾」，
   末尾那条搬完还在末尾，顺序不变 → 这条断言**抓不到这个变异**。
   换成第 1 条才能看出重排。**「移动类」断言必须用不在端点上的元素。**
2. `expectRed` 只写「拖回当天」，而实际红的是冒烟用例
   「拖回今**天**的日期格」—— 名字对不上关键词 → 判成 ~。
   **expectRed 要把可能变红的用例名都列上**（我补了「拖回今天」）。

**单点复验配方**（不用重跑 13 分钟全量）：
```bash
node scripts/mutation-run.mjs apply <idx>
npx vitest run <相关测试文件> > .vitest-mutation.log 2>&1
node scripts/mutation-run.mjs judge <idx>     # 期望 {"verdict":"caught",...}
git checkout -- <被改的文件>
```
⚠️ `git checkout -- <file>` 还原的是 **index** 里的版本，不是 HEAD ——
所以提交过再跑就行（工作区干净是前提，脚本会先查）。

**变异脚本的脏检查会把重定向日志算成脏** ——
`npm run mutation > .mutation-progress.log` 写进仓库根 = `?? .mutation-progress.log`
= 直接拒绝启动。日志要写到仓库外（`$TEMP`）。

## 主理人实测抓到的 bug：移过来的待办是灰字（当轮修复）

**症状**（截图）：拖到别天的待办，打开目标天显示灰色字体；圈号是数字、
没有删除线 —— 所以**不是** `done` 的灰（那是 `text-dim` + ✓ + 删除线）。

**根因**：灰 = `opacity-40` = 拖拽中的半透明高亮卡住了。
高亮存在 TodoList 的**模块变量 `draggingId`** 里，只在行的 `onDragEnd` 清；
而跨天搬运在 drop 瞬间把**源行卸载**，dragend 冒泡不到根容器（React 18
监听器挂在根上）→ id 永远留着 → 之后那条待办一挂载就带着半透明。

**教训（比这个 bug 值钱）**：上一轮我修的是「跨区通道 payload 要清」，
但**同一份语义存了两份状态**（payload + draggingId），清了一份漏了另一份。
修法不是再补一处清理，而是**删掉第二份** —— 高亮直接从 payload 推导
（`useDraggingId` 订阅 `subscribeDrag`，返回 `p?.from === 'todo' ? p.id : null`）。
**凡是「拖拽中」这类瞬时状态，只留一个来源；多一份就多一个要同步的地方。**

**为什么 `text-dim` 和 `opacity-40` 要分清**：两者都是「灰」，
但诊断意义完全不同 —— 前者是产品状态（已完成），后者是 UI 残留状态。
写断言时判的是 `opacity-40`（类名），不是颜色值。

**新增**：冒烟 2 条（拖动中半透明 → 松手恢复；拖到别天后目标天不带半透明）
+ 第 24 个变异（日历 drop 后不清通道）。265 用例。
