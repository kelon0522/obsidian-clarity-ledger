## Clarity Ledger · 上架前审查与修复

用户给了 icon.png 与 screenshot.png（两项上架资源已解决），要求修完审查里其余的问题。

### 硬阻断（本来会让上架直接失败）

- **`.github/workflows/release.yml` 里 `draft: true`** —— 最致命的一条。
  Obsidian 走 GitHub API 取**已发布** Release 的附件，draft 对外不可见，
  症状是「装了更新装不上」且社区页点进去 404。已改 `draft: false`。
- **仓库没有 `package-lock.json`**，而 release 与 CI 都用 `npm ci` → 必然失败。
- release 流程里补上 `npm test`（原来只跑 build）：这个项目的用例管的是
  「错了但不报错」的地方（拖拽落位、迁移不覆盖），发出去只能等下版本才能修。

### 样式污染用户 vault（真实事故，且完全静默）

`styles.css` 是**整个 vault 全局加载**的，而源码里：

- `prefers-reduced-motion` 写的是裸 `*` → 用户给 Obsidian 设了「减少动效」后，
  装了本插件，**所有界面**（含其他插件）的动效被压到 0.01ms。
- `:focus-visible` 也是裸的 → 键盘 Tab 一下，vault 里所有可聚焦元素套玫红描边。

修的时候踩了第二层坑：**加了 `.cl-root` 前缀还留在 `@layer base` 里是不够的** ——
Tailwind v4 处理 layer 时重写选择器、把前缀剥掉，产物里又变回裸的。
实测确认：源码改对了，产物里查无 `.cl-root :focus-visible`，只剩裸的。
**这与「日历隔离层必须留在 @layer 外」是同一个病。**

断言写在两侧：源码侧 `src/config/alias.test.ts`（含「必须在 @layer 外」），
产物侧 `scripts/verify-build.mjs`。

### main.tsx 的两处

- `open-today` 命令有死代码（`const s = ...; void s`）与竞态：
  三句并发导致 `setCur` 可能被随后的 `store.load()` 覆盖，表现为「停在昨天」。
  改成顺序执行的 `openToday()`，并给 store 加了 `setCalMonth`。
- `onunload` 是同步接口，救不了「250ms 防抖窗口内关掉 Obsidian 丢最后一次编辑」。
  真正兜住的是新加的 `flushOnBlur()`：拦window blur / visibilitychange 立刻落盘。

### 测试跨平台

`npm test` 与 `npm run mutation` 原来写死 `bash scripts/*.sh` —— 没装 Git Bash 的
Windows 贡献者根本跑不了。改成 node 驱动（`scripts/test.mjs`、`scripts/mutation.mjs`），
node 拿不到子进程输出时自动落到 shell 版（这份机器上就是如此，`spawnSync` 报 EBUSY）。
shell 版保留并标注为回退路径。

### 环境相关的坑（这台机器）

- node 里 `spawnSync` 必失败（EBUSY / status null / 无输出），bash 直跑正常 ——
  **别把它当成代码 bug**。
- `npm install` 挂在 esbuild postinstall（同一原因）。生成 lock 要用
  `--package-lock-only`，再用 `npm run lock:fix`（新增脚本）补 22 个
  esbuild 平台二进制的空壳条目，否则 `npm ci` 报 `TypeError: Invalid Version`。

### 变异测试抓到了我自己的问题（值得记）

新加的三条变异第一次跑，两条报「这个变异是假的 / 从未被验证过」。
真实原因不是断言写错，而是 **CRLF**：`src/index.css` 在 Windows 上是 CRLF，
变异定义里写的是 LF，正则匹配不上。
`applyMutation` 早先只给 `string` 分支做了行尾适配，正则分支漏了 —— 已补。
新写的跨行变异一律改用 `string`。

这条印证了项目里那句话：「测试全绿不等于测试有效」——
如果当时信了「断言写错了」而去改断言，就等于白改。
