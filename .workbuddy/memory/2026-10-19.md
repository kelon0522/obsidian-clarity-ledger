## 修复：待办落点红条残留（取消拖拽后不消失）

- 现象：把第 1 条拖到第 3 条上（行 3 亮起红条），再拖回原位松手，红条留在行 3。
- 根因：`hint` 是 `TodoList.Row` 的**每行私有 state**，清理只有两条路 ——
  命中行的 `drop` 和**源行**的 `dragend`。行 3 既不是源也不是最终落点
  （拖回原位后命中源行自己），永远收不到清理通知。
  同一根因的另一面：从行 3 横移到行 5，行 3 的红条也下不来（两条同时亮）。
- 修法：落点提示提升到 `dnd/shared`，与 payload 同一条通道（全局唯一），
  `setDragPayload(null)` 时一并清 `dropHint`。Row 改用 `useDropPos(id)` 订阅。
  - `overRow` 里 `id === t.id`（拖回自己）显式 `setDropHint(null)` —— 松手前就不该再亮。
  - `dropRow` 用 `getDropHint()` 同步读模块变量，**原先的 ref 兜底不再需要**
    （dragover 每次同步写入，drop 读到的必然最新）。
  - `dropAtEnd` / `onDragEnd` 也走同一条清理路径。
- 测试：`ledger.smoke.test.tsx` 新增 2 条回归（拖回原位松手 / 横移到另一行），
  先确认双红再修。`fireDrag` 增加可选 `clientY`（jsdom 的 rect 全 0，
  正数落在下半 = after）。
- 验证：`npm test` 281 条全绿；`npm run build` 全通过。
- 未动：`Calendar` 的 `hoverKey` / `Track` 的 `hoverM` 是单组件内的唯一 state，
  切格会覆盖、且有 dragleave，不在本次范围。
