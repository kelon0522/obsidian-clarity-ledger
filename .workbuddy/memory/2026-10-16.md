## 新功能：「移到今天」按钮 —— 批量搬迁某天的未完成待办

主理人需求：在某一天的页面里，把未完成的待办移动到今天。先出方案确认后实施
（用户拍板用默认项：通用 action `moveUnfinishedToDay(toKey)` / 不给撤销 /
不弹确认框 / 按钮放待办区头部 / 未来日期也允许搬）。

### 实现

- **store**：`src/store/index.ts` 新增 `moveUnfinishedToDay(toKey)`，
  放在 `moveTaskToDay` 后面。规则逐条对齐单项搬运，不发明新语义：
  只搬 `act == null`、字段原样、按原顺序追加到目标天末尾、目标天 `day_` 建档、
  目标天跑 `reflow`、`toKey === cur` 或无未完成项 → no-op 且不建目标天、
  两天都 `markDirty`、toast 报条数 `undoable=false`。
  沿用了 moveTaskToDay 的「守卫只写一处」写法（act 判断只在 set 外面的
  预读里做，set 内只兜「找不到」）—— 两处都写会让单行变异被掩盖。
- **UI**：`src/components/TodoList.tsx` 头部提示行右侧加 `Btn`「移到今天 · N」。
  显示条件 `cur !== todayKey && n > 0`。`Btn` 没有 className prop，
  用外层 `<span className="ml-auto">` 推右，没动共享组件。
- **测试**：store +10 条、冒烟 +4 条（按钮显隐 ×3 + 点击链路 ×1）；
  变异 +4 条（act 过滤 / 批量 reflow / 空搬守卫 / 按钮显示条件）→ 共 28 个。
  变异 needle 全部先本地验证过能匹配（`applyMutation` 的 changed 检查）。
- **文档**：README.md / README.zh-cn.md 三栏联动表各加一行 +
  「已完成的不能拖」段补一句按钮同规则；CHANGELOG [未发布] 新增条目；
  README 开发段过时的用例数/变异数改成真实值（279 / 28）。

### 踩到的一个坑（测试预期写反了）

第一条写的「源天剩余任务的顺序不变」预期成 `[1, 3]` —— 那是**单项**搬运的
预期（搬走 2，剩 1、3）。批量版搬走的是所有未完成，剩下的是已完成的。
改成「完成 1、3 → 搬走 2 → 源天剩 [1,3]、目标天得 [2]」才真的验证到顺序。
**批量语义下「剩余」指的是已完成的那几条**，写预期时容易按单项版惯性写错。
